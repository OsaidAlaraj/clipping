# Product principles (the owner's standards, written once; every session reads this first)

The owner has said all of this many times. Do not make them say it again.

1. **Automation means the system does the work, not that it moves buttons.** The main purpose is: for a campaign, find the BEST shots in a long video and produce finished clips that beat what social-media editors and templates produce. Choosing good moments is the core feature. A pipeline that runs but picks weak moments has failed.
2. **Campaign level.** Every output obeys the campaign: its rules, assets (logo required or forbidden), source whitelist, disclosure policy, hook rules, deadlines, account requirements. Real briefs are in `docs/briefs/real-briefs.md`; the gaps are in `docs/campaign-requirements-audit.md`.
3. **This is a mature field: reuse, do not rebuild.** Before building anything, search for what people already built (GitHub repos with stars/activity/licence/issues, creators' guides, forum and Reddit experience, reviews of commercial tools such as OpusClip, Vizard, Klap, Submagic). Pick the best by evidence and measure it on real footage. Build from scratch only when nothing measurably beats the existing option, and say why. Private local use: GPL/AGPL are fine, avoid non-commercial licences.
4. **Measure, do not claim.** Bake-offs on real videos; adopt only measurable winners; report numbers, including failures. Never say "works" without a run.
5. **One feature, one place.** If a capability exists (for example add a video by link), it must be reachable from every screen where it makes sense, through the same component. Never two different forms for the same job. Keep an information-architecture map (`docs/ia-map.md`) and update it with every screen change.
6. **Flows must feel human.** Few taps, no surprising redirects, the next step is always obvious, state is never lost, errors are plain sentences with the fix. Social-media-smooth (measured), mobile first, English and Arabic from day one.
7. **The front end must look designed by a person, not generated.** The Videos (review feed) page is the bar every other screen must reach. Distinct visual identity, real hierarchy, restraint, motion with purpose, real content shown (not placeholder cards). No generic dashboards, no gradient-and-card sameness.
8. **Hooks and captions at viral level.** Human, funny, trend-aware openers (POV:, Nobody:, Me when ...), short, specific to the clip, no formal or AI-sounding phrasing, Arabic as spoken Jordanian/Levantine. Templates must match or beat what top short-form editors ship.
9. **Do not say "I can't".** Use the tools available: the owner's signed-in Chrome (read pages, read Notion/Docs/marketplaces), `gh`, web search, Consensus, subagents. If something truly needs the owner (a password, a token, a download from a private folder), say exactly what and why, once.
10. **Token discipline (the owner's plan has a weekly limit).** Heavy work runs as scripts and writes to files; chat replies are short; read files with targeted ranges and greps, not whole; one full test suite at a time (lock file `.data/tmp/suite.lock`), `-n 2`, `TEMP`/`TMP` on `L:\Projects\Clipping\.data\tmp`; no repeated explanations; ask the owner only when a decision is theirs.
11. Standing safety rules: no automated posting without the owner's confirm; no VPN/anti-detect/bots/bought views/device farms/duplicate-evasion; never automate Discord user accounts (self-bots are banned by Discord); never print `.env` values; everything on drive L.
